# TraceTracking

TraceTracking 是一个只读终端文件浏览器。左侧按时间排列项目变更，右侧展示所选版本的完整正文。绿色 `+` 标出新增行，黄色 `~` 标出改写行，红色 `−` 表示此处发生删除。所有操作都能通过键盘完成。

## 启动

安装 Rust 稳定版和本机 C/C++ 构建工具后，在本仓库运行：

```sh
cargo install --path . --locked
tt .
```

Windows、macOS 和 Linux 使用相同命令。也可以直接执行 `cargo run --release --locked -- .`。默认只监听当前项目，在独立终端执行 `tt watch <目录>` 可以持续记录，Ctrl+C 结束。同一项目的多个窗口共享一个记录器。

## 浏览

| 按键 | 操作 |
| --- | --- |
| ↑ ↓ / Enter / Esc | 预览、进入正文、沿原路返回 |
| t / g | 时间轴与最近文件切换、回到最新记录 |
| x | 只看 Git 变更 / 恢复全部 |
| `[` / `]` | 跳到上一处或下一处变化，正文顶部显示当前位置和变化总数 |
| `d` | 在正文和行级对比之间切换，保留当前变化位置 |
| PgUp / PgDn | 按当前终端高度向前或向后翻一页 |
| z / f / H | 折叠一分钟内相邻的同文件保存、按当前目录筛选、返回浏览起点 |
| h / r | 查看文件历史、打开引用与定义候选 |
| / | 搜索，Tab 选择路径、当前正文或历史变更，Enter 确定 |
| p / i | 切换或添加项目、选择忽略规则 |
| G | 查看所选路径的最近 100 条 Git 提交，进入版本后用 d 与事件快照对比 |
| ? / q | 帮助、退出 |

鼠标滚轮在时间轴上切换记录，在正文上滚动当前文件，在项目、引用和忽略等列表中移动选中项。长路径在左栏显示为「首级目录/…/文件名」，选中项的完整相对路径显示在页首。

查看某行的引用时，先按 Enter 进入正文，用 ↑↓ 移到目标行，再按 `r`。查询在后台执行。结果出来后用 ↑↓ 预览，按 Enter 跳转，按 Esc 取消查询或逐层返回。

`t` 在时间轴和最近文件之间切换。应用会后台准备另一视图的列表和正文预览，已有缓存时直接切换并恢复该视图的读取位置。切换后分隔线会短暂扫过高亮。

正文和 diff 中的长行会随终端宽度自动折行，续行沿用同一源行的语法高亮，行号和变更标记只在首行显示。按 `d` 查看对比时，新增行用暗绿底色，删除行用暗红底色。

普通目录的基线使用文件修改时间，后续追踪到的新增、修改、删除和移动仍会显示事件类型。Git 项目在左栏额外显示两格工作区状态，左格为暂存区，右格为工作区。比如 `·M` 是未暂存修改，`M·` 是已暂存修改，`MM` 是两边都有改动，`??` 是未跟踪文件。黄色表示未暂存修改，绿色表示暂存或新增，青色表示未跟踪，红色表示删除或冲突，紫色表示重命名、复制或类型变化。

在时间轴或最近文件按 `x`，只显示当前有 Git 状态标记的文件记录，切换视图时会保留筛选。再按一次恢复全部。`.gitignore` 忽略的未跟踪文件会被排除，已跟踪文件的改动仍按 Git 状态显示。

时间轴中的 A、M、D 表示新增、修改和删除，O 表示再次打开时观察到的内容差异。系统提供成对移动事件时记录 R，其余情况保留观察到的新增和删除。浏览历史期间按 g 可以查看新记录。

## 追踪与存储

普通目录可以直接追踪。监听器合并短时间内的文件系统事件，记录能够读取到的稳定版本。应用退出期间的中间保存无法恢复。Git 功能按需调用系统 Git。

版本和索引存入系统本地应用数据目录中的 `TraceTracking/history.sqlite3`。可用环境变量 `TT_DATA_DIR` 指定数据目录。相同内容复用一份快照。UTF-8 文本的正文上限为 1 MiB，更大文件或二进制文件只记录事件。历史数据库随项目变化增长，当前版本保留全部记录。

正文和 diff 支持 Java、Python、TypeScript、JavaScript、Rust、Markdown、YAML 和 XML 的语法高亮。支持 Java、Rust、TypeScript、JavaScript、Python 声明的 Tree-sitter 索引，以及本地路径、Markdown 链接、XML 的 href/src/resource 等属性和配置路径引用。定义候选依据名称匹配；引用面板使用当前项目索引，预览会显示目标路径和行号。

## 忽略与来源

默认跳过 .git、node_modules、target、dist 和 __pycache__。规则按项目保存，支持 gitignore 风格的匹配。目录前的 / 表示从项目根匹配。选中任意文件按 `i`，可以选择该文件、扩展名或从直接父目录到项目根下的任意一级父目录。

```sh
tt ignore . "*.log"
tt ignore . "/apps/web/dist/"
tt unignore . "*.log"
```

AI 工具可以在成功写入后调用可选 hook。传入项目目录、写入路径和会话来源，路径和快照哈希匹配后显示来源。示例：

```sh
tt hook . src/main.rs "Claude Code · session-42"
```

没有来源证据的保存显示“来源未知”。hook 需要在调用方配置，安装程序不会修改 AI 工具的设置。

## AI 会话追踪

首次按 `a` 打开 AI 视图时，可以用空格或鼠标勾选当前目录关注的工具，按 `n` 登记自定义工具，按 `h` 查看当前工具的 Hook 接入方式，按 `Enter` 保存。以后打开会话面板可按 `c` 修改。关注设置按项目目录保存在应用数据里，影响会话面板、顶部活动和时间轴图标。文件详情仍可以查看已有的来源证据。

在 Hook 接入页按 `c`，可复制 Claude Code 或 Codex 的配置生成命令，或复制自定义工具的 JSON 示例。示例已填入当前项目路径。Linux 桌面环境使用 `wl-copy`（Wayland）或 `xclip` / `xsel`（X11）。

按 `a` 打开当前目录的会话面板。方向键选择会话，`Enter` 筛选它的已关联变更，`Esc` 原路返回，`d` 查看对应 diff。顶部显示当前目录的近期会话和收到目标路径的在途写入。会话从父目录启动时，写入当前目录也会出现在面板里。

确保 AI 工具能从 PATH 找到 `tt`，再从下面命令生成 Hook 片段，合并到工具的 Hook 配置中，保留已有 Hook。

```sh
tt ai-hook-config claude-code
tt ai-hook-config codex
```

Claude Code 可合并到 `.claude/settings.local.json` 或用户设置。Codex 可合并到项目的 `.codex/hooks.json` 或用户的 `~/.codex/hooks.json`，并通过工具的 Hook 界面确认配置。默认接入 Claude Code 的 `Edit` / `Write` 与 Codex 的 `apply_patch`。前后 Hook 需要按工具默认的同步方式执行，以便在下一次写入前记录指纹。Hook 只写入必要的本地事件，正文查询、归因和会话汇总在 TraceTracking 后台执行。

已验证的预期内容指纹和观察到的文件快照一致，且一个工具操作能唯一对应当前项目的一次变更时，时间轴显示工具标识。Shell、未知编辑方式、快照合并和竞争写入可能缺少可确认的来源。应用会显示「可能相关」「归属不明」或「来源未知」。超过正文快照大小的文件仍可出现在会话活动里，精确归因需要可比对的快照。

### 自定义工具

向 `tt ai-event` 的 stdin 发送一条 JSON。以下示例注册项目下的一个自定义会话。

```json
{
  "version": 1,
  "tool": "studio",
  "instance": "local",
  "session_id": "session-42",
  "cwd": "/path/to/project",
  "phase": "session_start",
  "title": "更新配置"
}
```

事件阶段支持 `session_start`、`session_idle`、`session_end`、`write_start`、`write_finish` 和 `write_fail`。写入事件需提供同一次工具调用的 `call_id` 和 `files` 数组。每项必填相对 `cwd` 或绝对的 `path`，可带写入前的 `before` 和预期结果的 `expected_after`。两者用 SHA-256 十六进制表示，文件不存在用 `-`。完成事件可带工具实际捕获的 `observed_after`，省略时 `tt` 在接收事件时读该文件的指纹。工具可额外提交 `turn_id` 和 `model`。原始 Hook JSON、补丁正文和聊天记录保留在各自的工具里。

在关注设置中按 `n` 可为当前项目登记工具 ID、名称、图标和颜色。也可以在应用数据目录放置 `agents.json`，为各项目提供共享的工具配置。设置环境变量 `TT_ASCII=1` 使用 ASCII 图标。

```json
{
  "studio": { "name": "Studio Agent", "icon": "◈", "ascii": "S", "color": "#D29FFF" }
}
```
